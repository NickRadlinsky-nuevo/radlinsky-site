# Пайплайн публікації номера журналу «ДентАрт» на radlinsky.com.ua

Повний алгоритм для перенесення одного номера ДентАрту (усі статті) на сайт.
Відпрацьований на 2020 №1-4, 2022 №1-4, 2023 №1-4, 2019 №1-4 (12+ номерів).
Інструменти-скрипти лежать поруч у `_templates/dentart-tools/` (git-tracked,
переживають нову сесію — на відміну від `scratchpad/`, який session-specific
і зникає між діалогами).

## ⚠️ Стандартні правила (незмінні для будь-якого номера)

1. **Текст переносити ДОСЛІВНО і ПОВНІСТЮ** — сокращать/переказувати НЕДОПУСТИМО.
   Резюме/абстракти можна не дублювати окремим блоком (вони йдуть у meta description),
   але основний текст статті — 1:1 з журналом, включно з вітальнями/інтерв'ю.
2. **Підписи до кожного фото зберігати дослівно**, якщо вони є в оригіналі (`galc()`, не `gal()`).
3. **Перевіряти ВСІ статті номера**, не тільки вибіркові.
4. Публікувати номер **цілим блоком** (усі статті → мініатюри → секція в statti.html → один git push).
5. gh-акаунт має бути `NickRadlinsky-nuevo`. Прибирати email авторів (лишати тільки
   `info@radlinsky.com.ua` у футері). Рекламу/промо пропускати. Повний список літератури
   (`<ol class="refs">`) переносити цілком. Коміт-повідомлення закінчується
   `Co-Authored-By: Claude <модель> <noreply@anthropic.com>`.
6. Номери 2021 року (лише 2, обидва російською) — пропускаємо.

## Крок 0. Підготовка нового номера

```bash

```

Скопіювати інструменти з persistant-репо у робочу сесію:

`_templates/dentart-tools/build.py` напряму, він уже актуальний.

## Крок 1. Карта номера (зміст + зсув сторінок + реклама)

```bash
pdfinfo "<PDF>" | grep Pages
pdftotext -f 4 -l 5 "<PDF>" -           # зміст номера, зазвичай на стор. 4-5
```

**Визначити зсув:** журнальна сторінка + N = сторінка PDF. Перевіряється звіркою
номера сторінки в тексті статті (внизу колонтитула) з фактичною сторінкою PDF.
Для всіх номерів 2019-2023 зсув був **+2** (обкладинка+титул), але завжди звіряти
заново — буває інакше.

**Скан усіх сторінок одним проходом**, щоб знайти рекламу:
```bash
for i in $(seq 1 <total>); do
  t=$(pdftotext -f $i -l $i "<PDF>" - 2>/dev/null | tr '\n' ' ' | tr -s ' ' | cut -c1-90)
  printf "%3d| %s\n" $i "$t"
done
```
Сторінки без розпізнаваного тексту статті (порожні/лого/реклама) — перевірити
рендером (`pdftoppm -f N -l N -r 55 -png`) і занести в список пропусків.
Рубрика «Інтер'єр стоматологічної клініки» — теж не публікуємо.

## Крок 2. ⚠️ ПЕРЕВІРКА ОРІЄНТАЦІЇ (обов'язково перед масовою обробкою)

Це найкритичніший крок. У 2020 №4 зайвий `flip()` зламав усі 196 фото номера,
бо було виправлено діагностику лише по 8 портретах замість перевірки всього масиву.

```bash
# витягнути по одному raw-портрету (обличчя людини — асиметричний, легко звірити)
# з 4-5 різних статей номера
pdfimages -j -p -f <p1> -l <p1> "<PDF>" test1
pdfimages -j -p -f <p2> -l <p2> "<PDF>" test2
# ... і т.д. для кожної статті

python3 sheet.py orient.png test1-im-*-000.jpg test2-im-*-000.jpg ...
```
Прочитати `orient.png` (Read tool). Порівняти з тим, як обличчя мало б виглядати
природно (очі горизонтально, не догори ногами, не дзеркально).

- Якщо всі ОК → `FLIP = False` у `proc.py`, писати в docstring: «pdfimages віддає
  зображення вже правильно, flip НЕ застосовувати».
- Якщо перевернуті → `FLIP = True`, і **обов'язково перевірити після обробки всі
  оброблені фото номера ще раз** (не тільки перших кілька) — робити це вибірково
  по 1-2 фото з кожної статті через `sheet.py`, а не «на око» по перших восьми.

## Крок 3. По кожній статті: витяг тексту й зображень

```bash
mkdir -p <article>/raw
pdftotext -f <a> -l <b> "<PDF>" src/<article>.txt          # без -layout — чистий порядок читання для 2 колонок
pdftotext -layout -f <a> -l <b> "<PDF>" src/<article>_layout.txt  # ⚠️ ДОДАТКОВО, якщо в статті є таблиці — layout-версія їх не ламає
pdfimages -j -p -f <a> -l <b> "<PDF>" <article>/raw/im
```
`-p` у `pdfimages` додає номер сторінки в ім'я файлу (`im-042-007.jpg`) — це і є
прив'язка raw → сторінка джерела, критично для кроку 4.

Порахувати обсяг (орієнтир перевірки повноти пізніше):
```bash
python3 -c "import re,io; t=io.open('src/<article>.txt',encoding='utf-8').read(); print(len(re.findall(r'[А-Яа-яІіЇїЄєҐґA-Za-z]{2,}', t)))"
```

## Крок 4. ⚠️ АЛГОРИТМ ВІДПОВІДНОСТІ ЗОБРАЖЕНЬ ПОРЯДКУ ВЕРСТКИ

**Головна пастка: порядок файлів у `pdfimages` (за номером сторінки + порядком
у PDF-потоці) НЕ завжди збігається з порядком фото на сторінці журналу.** Особливо
у сітках 2×3/3×3 — верстальник міг класти фото по колонках (1,3,5 / 2,4,6), а не по
рядках. Пропускати цю перевірку — гарантований шлях до переплутаних підписів.

Послідовність дій для КОЖНОЇ сторінки з фото:

1. **Рендер сторінки-джерела для звірки:**
   ```bash
   pdftoppm -f <N> -l <N> -r 88 -png "<PDF>" pg/p
   ```
   Прочитати (`Read`) — подивитись візуально, яке фото де стоїть, скільки їх,
   чи є підписи «Фото 1/2/3…» чи «а/б/в».

2. **Контактний аркуш raw-файлів цієї сторінки** (щоб бачити імена файлів поруч
   із вмістом):
   ```bash
   python3 sheet.py out.png <article>/raw/im-0NN-*.jpg
   ```
   Прочитати. Порівняти з рендером сторінки з кроку 1.

3. **Якщо порядок неочевидний** (сітка 2×3+, багато схожих кадрів «до/після»
   одного зуба) — використати `match_grid.py`, який ріже сторінку на комірки по
   заданій сітці і зіставляє з raw Угорським алгоритмом (не жадібним — жадібний
   плутається на майже однакових кадрах):
   ```bash
   python3 match_grid.py pg/p-NN.png <x0,y0,x1,y1 у частках сторінки> <rows> <cols> <article>/raw/im-0NN-*.jpg
   ```
   Дає ~85% влучань; **критичні комірки все одно звірити візуально** великим
   side-by-side crop (див. приклад нижче) — Угорський алгоритм не панацея.

4. **Побудова side-by-side для сумнівних пар** (коли треба на 100% впевнитись):
   ```python
   from PIL import Image
   page = Image.open("pg/p-NN.png"); raw = Image.open(".../im-0NN-XXX.jpg")
   # crop потрібної комірки зі page за координатами (частки → пікселі), покласти
   # поруч з raw в один Image.new(...), зберегти, прочитати Read tool'ом
   ```

5. **Якщо на сторінці є векторна графіка/схема/таблиця** (діаграми, рисунки з
   легендою, кольорові схеми) — `pdfimages` або взагалі її не витягне, або віддасть
   лише фрагменти-іконки легенди (крихітні 20×30px файли — це ознака, що справжнє
   зображення векторне). У такому разі:
   ```bash
   pdftoppm -f <N> -l <N> -r 300 -png "<PDF>" hi
   ```
   і вирізати потрібний прямокутник напряму з рендера через `crop_grid.py` або
   вручну PIL-кропом (координати підбирати ітеративно, звіряючи Read-ом, поки
   рамка не охопить весь рисунок з підписом). **Це ж стосується фотоколажів/
   композитів**, де на сторінці один шар накладений на інший (напр. тюбик засобу
   поверх фото зуба) — pdfimages віддасть два окремі шари, а треба один вирізаний
   з рендера кадр, що показує композит як його бачить читач.
   ⚠️ Перевірено: у деяких номерів схеми в pdfimages лежать **іншою мовою**
   (рос. замість укр.), бо журнал накладає текстовий шар зверху — тоді вирізання
   з рендера обов'язкове, інакше на сайт потрапить чужомовний текст у картинці.

## Крок 5. Обробка зображень (`proc.py`)

```bash
python3 proc.py <article_dir> <prefix> <raw1> <raw2> ... <rawN>
```
Аргументи `raw1..rawN` подаються **у порядку, встановленому кроком 4** (не в
порядку файлів на диску!). Скрипт перейменовує послідовно в `<prefix>-001.jpg …`
і кладе в `images/` сайту, з `CAP=1050`px, JPEG q84, EXIF-transpose, і `FLIP`
якщо потрібен (крок 2).

Якщо для сторінки знадобився прямий crop з рендера (крок 4.5) — зберігати той файл
одразу з правильним ім'ям `<prefix>-0NN.jpg` в `images/`, номер вписати в
послідовність вручну (не через `proc.py`).

## Крок 6. Написання `b_<article>.py`

Патерн (див. готові приклади в `scratchpad` попередніх сесій або в самих
опублікованих `.html` на сайті):

```python
import sys, os
sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "n2023-1"))
from build import build, gal, galc

P = "<prefix>"
G1 = galc([(2, "Фото 1. …"), (3, "Фото 1. …")], P)   # galc = з підписом
G2 = gal([4, 5], P, "альт-текст без підпису", cls="g2")  # gal = без підпису, cls: g2/g3/g4 = колонок у сітці

body = f'''      <div class="art-body">
<p class="lead">…</p>
{G1}
<p>…</p>
      </div>
{{REFS}}'''

refs = ["Автор. Назва // Джерело. – Рік. – С. X-Y.", ...]
def esc(s): return s.replace("&", "&amp;")
refs_html = ('      <div class="refs">\n        <h2>Література</h2>\n        <ol>\n'
             + "\n".join(f"<li>{esc(r)}</li>" for r in refs) + "\n        </ol>\n      </div>")
body = body.replace("{REFS}", refs_html)

build(
  slug="statti-<автор>-<тема-латиницею>",
  title="…", en_title="…",
  kicker="Рубрика · журнал «ДентАрт» <рік> №<номер>",
  author_html='Автор,<br><span>афіляція</span>',
  body=body,
  ogimg=f"{P}-002.jpg",     # ⚠️ БЕЗ префікса "images/" — build() сам додає
  desc="…", ogdesc="…",
  schema_type="ScholarlyArticle",  # або "Article" для нон-фікшн/інтерв'ю
  schema_authors=["Latin Name"],
  alt_headline="…",
)
print("built")
```

⚠️ Пастки:
- `body` — f-string, тому плейсхолдер літератури писати `{{REFS}}` (подвійні дужки),
  інакше `NameError`.
- `ogimg` без префікса `images/` — build() сам його додає; якщо передати з префіксом,
  вийде `images/images/...` в og:image.
- Таблиці — HTML-розміткою `<figure class="tbl"><figcaption class="tbl-cap">…</figcaption>
  <div class="tbl-wrap"><table class="dtable">…</table></div></figure>`, не картинкою.
- Формули — текстом з `<sub>/<sup>` у `<div style="...той самий стиль що .formula...">`,
  не картинкою (легше редагувати, краще для SEO).
- Інтерв'ю/вітальня — розмітка `<p class="q">–…</p><p class="a">–…</p>`, `.intro` для
  лід-абзацу, `.ack` для «Розмовляв(ла) …» в кінці.
- Якщо стаття розбита в журналі на дві частини по різних сторінках номера
  (напр. рубрика «Ваше рішення»: умова на одній сторінці, розв'язок — через 30
  сторінок) — об'єднувати в ОДНУ статтю на сайті, природним порядком читання.
- Якщо кілька коротких матеріалів під однією рубрикою на суміжних сторінках
  (напр. 3 замітки під шапкою «Міжнародна колегія стоматологів») — об'єднувати
  в один композитний допис з `<h2>` на кожен підматеріал.

## Крок 7. ⚠️ ПЕРЕВІРКА ПОВНОТИ ТЕКСТУ (`missing.py`)

Запускати для **кожної** статті одразу після білду:
```bash
python3 <article_dir>/b_<article>.py
python3 missing.py src/<article>.txt /Users/<user>/projects/radlinsky-site/statti-<slug>.html
```
Виводить список речень з джерела, яких не знайдено в опублікованому HTML.
Нормальні («очікувані») залишки:
- англомовний Abstract/Key words (за конвенцією сайту йде тільки в meta description);
- 1-2-словесні артефакти зшивання двоколонкової верстки pdftotext (типу «…курси
  вія фото» — це склеєні хвости сусідніх колонок, не реальний пропуск);
- текст, який вписаний просто в саму картинку (легенда діаграми) — не дублюється
  окремим текстом.

Якщо в списку є **цілі речення/абзаци реального змісту** — це реальний пропуск,
шукати в тексті джерела і дописувати в `b_<article>.py`.

## Крок 8. Валідація HTML статті

Вбудована в `build()` (виводить `imgs=N miss=0 moj=0` після кожного білду):
`miss` — відсутні файли зображень (має бути 0), `moj` — мojibake в alt-тексті
(подвійно закодований UTF-8 — теж 0).

Додатково для всього номера одразу:
```python
import re, os
from html.parser import HTMLParser
for f in ["statti-....html", ...]:
    h = open(f, encoding="utf-8").read()
    HTMLParser().feed(h)  # впаде на биту розмітку
    imgs = re.findall(r'src="(images/[^"]+)"', h)
    miss = [i for i in imgs if not os.path.exists(i)]
    mail = set(re.findall(r'[\w.\-]+@[\w.\-]+\.[a-z]{2,}', h)) - {"info@radlinsky.com.ua"}
    print(f, "miss=", miss, "mail=", mail)
```

## Крок 10. Секція в statti.html

Python-скрипт, що вставляє новий `<section class="issue">` з картками **перед**
секцією попереднього (свіжішого хронологічно) номера — секції йдуть новіші→старіші.
Патерн — знайти унікальний anchor (`<div class="issue-head"><h2>«ДентАрт» № X (YY)</h2>`
попереднього номера) і вставити блок карток перед ним. Кожна картка:
```html
<a class="scard" href="statti-....html">
  <div class="scard-img"><img src="images/statti-th-NN.jpg" width="520" height="347" loading="lazy" decoding="async" alt="Назва"></div>
  <div class="scard-body">
    <span class="scard-rub">Рубрика</span>
    <h3>Назва статті</h3>
    <span class="scard-auth">Автор</span>
  </div>
</a>
```
Після вставки — той самий валідатор з кроку 8, але на `statti.html`
(`href`-посилання теж перевірити на існування файлу).

## Довідково: типові грабельки з попередніх номерів

- **2020 №4**: масовий зайвий `flip()` — виправлено лише 8 портретів замість
  усіх 196 фото. Урок: контактний аркуш ≥330px на фото, не 140-175px — на дрібних
  перевернутий зуб виглядає правдоподібно.
- **matchTemplate проти рендерів PDF** — ненадійний, давав неправильні вердикти
  на вже перевірених файлах. Замінено на візуальну звірку side-by-side.
- **opencv 5.0.0** не має `CascadeClassifier` — якщо колись знадобиться
  детекція облич, ставити `opencv-python-headless==4.10.0.84`.
- **statti.html «змішування» секцій номерів** — картки одного номера потрапляли
  в чужу секцію при неакуратній вставці. Завжди перевіряти після вставки, що
  кожна картка в правильній `<section class="issue">`.
- **`ogimg` з подвійним префіксом** — `f"images/{P}-018.jpg"` замість `f"{P}-018.jpg"`
  дає `og:image=.../images/images/...`. build.py тепер сам захищається від цього,
  але краще одразу передавати без префікса.
- **Мojibake alt-атрибутів** — подвійно закодований UTF-8, виправляється:
  `re.sub(r'alt="([^"]*Ð[^"]*)"', lambda m: 'alt="%s"' % m.group(1).encode('latin1').decode('utf-8'), h)`.
- **Втрата `scratchpad/n2023-1/build.py` між сесіями** — відновлюється
  `rebuild_build_py.py` (шаблонізація вже опублікованої сторінки), або просто
  копіюванням `_templates/dentart-tools/build.py`.
